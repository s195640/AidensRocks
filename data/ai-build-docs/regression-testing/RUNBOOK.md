# Regression Suite — Runbook

How to run the regression suite, and how to extend it. Written for future AI sessions as well as people.

## Run everything

```bash
bash data/scripts/run-regression.sh            # or: powershell -File data/scripts/run-regression.ps1
bash data/scripts/run-regression.sh --keep     # leave the test stack running afterwards
```

The script runs these steps in order and prints a PASS/FAIL summary:
1. **Test stack:** starts it (`data/docker-compose/docker-compose-test.yml`).
2. **`client` lint.**
3. **`server` API tests:** Vitest + supertest.
4. **`client` browser tests:** Playwright, Chromium on desktop plus one mobile profile.
5. **Teardown:** stops the stack.

It exits non-zero if any step failed. On a browser failure, open `client/playwright-report/index.html`, which has traces and screenshots.

**Prerequisites:** Docker running, `npm install` done in `server/` and `client/`, and Chromium installed once with `npx playwright install chromium` in `client/`.

## Run one part

| What | Where | Command |
|---|---|---|
| Start/stop test stack | `server/` | `npm run test:db:up` / `npm run test:db:down` |
| API tests | `server/` | `npm test` (one file: `npx vitest run tests/api/auth-flows.test.mjs`) |
| API tests, watch mode | `server/` | `npm run test:watch` |
| Browser tests | `client/` | `npm run test:e2e` (one file: `npx playwright test e2e/rocks.spec.js`) |
| Browser tests, headed | `client/` | `npx playwright test --headed` |

## What it runs against (never dev or prod)

- **Postgres:** `localhost:5433`, DB `aidensrocks_test` (tmpfs, so it's gone on `down`).
- **Mailpit:** SMTP `:1026`, UI/API `http://localhost:8026`. Every email the server sends lands here.
- **Media:** `server/tests/.tmp/media`. Tests run with the server's cwd set to `server/tests/.tmp`.
- **Env:** `server/tests/setup/testEnv.mjs` *overwrites* the DB, mail and JWT settings, so neither `server/.env` nor the dev DB nor Gmail is ever used.
- **Browser runs:**
  - Playwright starts `npm run test:serve` in `server/` (the API on `:8001`).
  - It also starts `vite build && vite preview` with `client/vite.e2e.config.js` (on `:4174`, proxying `/api` and `/media` to `:8001`).
  - The dev `vite.config.js` (LAN HMR) is untouched.

The ports don't clash with the dev stack (5432/1025/8025/8000/4173), so both can run at once.

The **browser run** reseeds once at start.

## Adding to it

- **New API route:** add a row to `ROUTES` in `server/tests/api/auth-matrix.test.mjs` with its gate (`public`, `user`, `admin` or `gone`). This file is what catches a route mounted without the right auth.
- **New behaviour or bug fix:** add an API test in the closest `tests/api/*.test.mjs`. Tag it with an ID from `summary-issue-log.md` when it pins a bug.
  - Use `api()`, `bearer('admin')`, `sql()`, `waitForMail()` and `waitFor()` from the helpers.
  - Load server code through the helpers' `require`, never through an `import` of `src/`. That keeps one shared pool and one app instance.
- **New seed rows:** use fixed keys below 100 (sequences start at 100) and comment why each row exists. Add matching files in `media.mjs` if pages will show them.
- **UI behaviour:** add a browser test in `client/e2e/`.
  - Sign in with `signInAs(page, 'admin')`.
  - Fail on script errors with `trackErrors(page)`.
  - Stub API failures with `page.route(...)`.
- **CLAUDE.md UI rule:** CLAUDE.md asks that after a UI change the user does their own check first, before Claude runs browser checks. Running this existing suite as part of a regression pass the user asked for is fine.

## Gotchas

- **Windows:** sharp keeps image files open, which blocks deleting them, so the tests switch its cache off (`perFile.mjs`, `e2eServer.mjs`). Linux prod isn't affected.
- **Upload images:** sharp is lenient with truncated images. The "one file fails" case (S9) is therefore tested by calling `processImagesInBackground` directly on a prepared folder.
- **Map tiles:** OpenStreetMap requests from the map page fail offline. `trackErrors` ignores network noise.
